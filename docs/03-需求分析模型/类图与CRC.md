## 3. CRC 卡

> 每个核心类一张，至少覆盖待办、通知、订阅源、提醒规则。

### CRC：待办事项 TodoItem

| 职责 | 协作者 |
|---|---|
| 持有标题、截止时间、状态、归属用户 | User |
| 记录来源通知 | Notice |
| 状态迁移（草稿→已确认→进行中→已完成/已过期/已取消） | TodoStatusLog |
| 判断是否已过期 | — |

### CRC：通知记录 Notice

| 职责 | 协作者 |
|---|---|
| 持有标题、正文、来源链接、发布时间 | Source |
| 计算内容指纹用于去重 | — |
| 记录归类结果 | Course, Category |
| 检测改期 | — |

### CRC：订阅源 Source

| 职责 | 协作者 |
|---|---|
| 持有源地址、类型、状态 | SourceType |
| 触发抓取 | FetchTask |
| 连续失败后转失效 | FetchTask |

### CRC：提醒任务 ReminderTask

| 职责 | 协作者 |
|---|---|
| 持有计划发送时间与状态 | ReminderRule |
| 幂等消费（同一任务不重复发送） | — |
| 记录发送结果 | — |

## 4. 关键关系说明

| 关系 | 说明 | 多重性 |
|---|---|---|
| User — TodoItem | 一个用户拥有多个待办 | 1 : 0..* |
| Notice — TodoItem | 一条通知可生成多个待办草稿 | 1 : 0..* |
| Source — Notice | 一个源产生多条通知 | 1 : 0..* |
| TodoItem — ReminderRule | 一个待办可配置提醒规则 | 1 : 0..* |
