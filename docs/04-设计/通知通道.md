# 通知通道设计

> 对应单元：4 设计建模｜检查点：第 6 次课｜状态：v0.2 实现依据
> 相关需求：FR-17 提醒规则、FR-18 提醒投递与渠道绑定、NFR-3 提醒准点、R3 提醒丢失、R11 第三方服务可用性

## 1. 为什么不用学校渠道

学校提供了日程服务与消息服务（邮件、企业微信、微信模板消息），但实际投递不由这些接口保证：写进去的日程不一定会触发提醒，模板消息需要用户关注并授权，邮件额度全校共享。

因此本项目的提醒由**自己的服务端主动投递**，学校渠道只作为可选增强（写入校园号日程，方便用户在日历里看到），**不承诺提醒**。

## 2. 通道选型

| 通道 | 实现 | 接收端 | 凭据 | 定位 |
|---|---|---|---|---|
| 微信服务号（Server酱） | HTTPS POST | 微信「服务通知」 | 用户 SendKey | 主通道 |
| 微信服务号（PushPlus） | HTTPS POST | 微信「服务通知」 | 用户 Token | 主通道备份 |
| 邮件 | SMTP | 学生邮箱 | 全局 SMTP 账号 | 兜底 |
| 站内消息 | 数据库 | 系统页面 | 无 | 兜底（打开才看到） |

选择第三方服务号的原因：个人无需公众号资质、无需认证与审核、无需备案，扫码即得凭据，一条 HTTPS 请求即可到达微信。

## 3. 抽象

```
DeliveryService（上层：决定发给谁、发什么、失败怎么办）
        │
        ├─ Notifier.send(target, Outbound) -> Result
        │     ├─ ServerChanNotifier
        │     ├─ PushPlusNotifier
        │     ├─ EmailNotifier
        │     └─ InboxNotifier（站内）
        │
        └─ DeliveryLog（每次尝试落一条）
```

约定：

1. **send 不抛异常**，一律返回 `Result(ok, code, detail, latency_ms)`；网络错误、鉴权失败、业务错误都折算成 `code`
2. **target 是接收者凭据**：服务号是 SendKey/Token，邮件是邮箱地址；通道本身无状态
3. **降级由上层决定**：按用户设置的"主通道 → 兜底顺序"依次尝试，任一成功即止
4. **投递记录幂等**：`UNIQUE(reminder_task_id, channel)`，重试前先查是否已成功

## 4. 失败分类

| code | 含义 | 处理 |
|---|---|---|
| `ok` | 已提交给服务商 | 记成功 |
| `no_target` | 用户未绑定该通道 | 跳过，不重试 |
| `auth` | 凭据失效（HTTP 401/403） | 不重试，通知用户重新绑定 |
| `network` | 连接失败或超时 | 重试 2 次（1.5s、3s 退避），仍失败则降级 |
| `serverchan_<code>` / `pushplus_<code>` | 服务商业务错误 | 不重试，降级 |
| `not_configured` | 通道未装配（如 SMTP 未配） | 跳过 |
| `smtp_error` | 邮件发送失败 | 降级到站内 |

## 5. 绑定流程

```
学生：网页「我的 → 通知渠道」→ 选择"微信服务号"
        ↓ 页面给出引导：扫码关注 → 复制 SendKey
学生：粘贴 SendKey → 保存
        ↓
服务端：立即投递一条"绑定成功"测试消息
        ↓ 成功则标记 verified_at，失败提示重新粘贴
```

同一用户可绑定多个通道，并指定主通道；未指定时按系统默认（服务号 → 邮件 → 站内）。

## 6. 准点率口径（NFR-3）

- 验收对象是**服务端发出投递请求的时间**：计划时间 ±60s 内发出
- 到达时间由服务商决定（实测秒级），不计入验收
- 调度器 tick 30s，任务落库 + 启动补扫，避免重启丢提醒

## 7. 与学校渠道的关系

| 能力 | 是否依赖学校接口 | 说明 |
|---|---|---|
| 提醒投递 | 否 | 服务号 + 邮件 |
| 待办同步到校园号日程 | 是（可选） | 让用户在日历里看到，不承诺提醒 |
| 学校邮件/企业微信推送 | 是（可选） | 若接口实际可用，可作为额外通道接入 |

## 8. 安全与隐私

- SendKey/Token 视为凭据：加密存储、日志脱敏（只留前 4 位）
- 消息正文只放"课程名 + 时间 + 地点 + 短链"，不传学号、成绩、身份证等
- 第三方服务商可见消息内容，属于已接受的取舍，写进隐私说明

## 9. 演示脚本

1. 学生在网页绑定 SendKey，立刻收到"绑定成功"
2. 确认一条考试待办，提醒时间设为 2 分钟后
3. 关闭网页，等手机微信「服务通知」弹出
4. 后台「投递记录」显示：通道 serverchan、耗时 xx ms、结果 ok
5. 故意把 SendKey 改错，再触发一次：记录变红、自动降级到邮件，主流程不受影响
