## 构件 1：ingest（抓取与去重）

### 职责

按调度周期拉取订阅源，归一化为通知记录，按内容指纹去重后入库。

### 类设计

| 类 | 职责 |
|---|---|
| `SourceAdapter`（抽象） | 定义 `fetch` / `normalize` 契约 |
| `RssAdapter` | RSS / Atom 源 |
| `GithubAdapter` | GitHub 仓库提交与发布 |
| `ManualAdapter` | 手动导入 |
| `IngestService` | 编排抓取、去重、入库、健康计数 |

### 关键算法：内容指纹去重

```
fingerprint = sha256(source_id + 源内唯一键 + 标题归一化 + 正文归一化前 512 字)
入库前按 (source_id, fingerprint) 查重；命中则跳过并更新 last_seen_at
```

### 异常与降级

| 异常 | 处理 |
|---|---|
| 网络超时 | 记失败计数，本轮跳过，下轮重试 |
| 解析失败（结构变化） | 记失败计数 + 告警；连续 3 次 → 源转「失效」→ 降级手动导入 |
| 重复条目 | 静默跳过，不报错 |

### 单元测试要点

- 同一 feed 重复投喂 10 次，记录数不变（NFR-2）
- 结构损坏的 feed 不抛未捕获异常，源状态正确迁移

## 构件 2：reminders（提醒调度）

### 职责

按提醒规则生成提醒任务，到点发送并回写状态；服务重启后补扫未发送任务。

### 关键算法：幂等消费 + 启动补扫

```
启动时：SELECT * FROM reminder_task WHERE status='pending' AND plan_time <= now()
消费时：UPDATE ... SET status='sending' WHERE id=? AND status='pending'（乐观锁）
发送失败：status='failed'，重试次数 +1，超过 3 次标记 dead 并告警
```

### 单元测试要点

- 同一任务并发消费两次，只发送一次
- 模拟重启后补扫，遗漏任务被补发
