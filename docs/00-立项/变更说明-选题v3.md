# 选题变更说明：v2 → v3

> 变更日期：2026-11-20 ｜ 变更类型：选题定位与需求范围 ｜ 状态：已提交评审

## 1. 为什么改

立项阶段做了一轮可行性探测（脚本与结果见 [`probe/`](../../probe/)），发现 v2 有三个前提不成立：

| v2 的前提 | 实测结果 | 影响 |
|---|---|---|
| 官网有 RSS，可做通用订阅 | 4 个站点 × 4 条常见 feed 路径全部 404 | "多源订阅"的一半能力没有数据源 |
| 可以自动获取"新作业" | 237 个接口中"作业"命中 0 个 | 作业类待办无来源 |
| GitHub OAuth 作主登录即可 | 拿不到学工号 | 无法访问课表、考试、通知等校内数据 |

同时发现一个 v2 没利用上的资源：**校内结构化接口本身就能给出时间、地点、课程**，比"从通知正文抽截止时间"可靠得多。

## 2. 改了什么

| # | 变更 | 说明 |
|---|---|---|
| 1 | 定位：信息聚合器 → **校园待办中心** | 主源从"官网网页"改为"校内结构化接口"，官网/GitHub/手动导入降为补充源 |
| 2 | 登录：GitHub OAuth → **学校统一身份认证** | 只有学校认证能提供学工号；GitHub 公开仓库读取本就不需要 OAuth |
| 3 | 新增第二节「数据来源与现有设施」 | 16 类来源、字段级说明，功能点必须锚定真实接口 |
| 4 | 待办生成拆两条路径 | 结构化源（考试/课表/毕设/实习/待办/催还）**自动确认**；文本源（通知正文）**草稿 + 用户确认** |
| 5 | 提醒改为双路径 | 学校日程服务投递（重复规则 + 多渠道）+ 本地任务兜底（准点率验收） |
| 6 | 删除 4 项、降级 2 项 | 删除 RSS、节假日顺延、图书"到期"提醒、学院源全覆盖；降级 OCR 与图书为提示 |
| 7 | 规模：用例 26 → 37，分析类 20 → 26，NFR 5 → 7，风险 5 → 10，FR 21 项 | 数据源变多、链路变长，需要更细的规格 |

## 3. 编号映射（旧 → 新）

v2 的 `UC-01 ~ UC-26` 与 v3 的 `UC-01 ~ UC-33` **不是一一对应**，不要直接沿用旧编号。

| v2 | v3 | 说明 |
|---|---|---|
| UC-01/02 GitHub 登录与绑定 | UC-01 学校统一身份认证登录 | 认证方式替换，绑定需求消失 |
| UC-03/04 订阅源增删停 | UC-11/12/13 | 新增"官网栏目""GitHub 仓库"两类源的独立用例 |
| UC-05 手动导入 | UC-14 | 不变 |
| UC-06/07/08 通知流 | UC-08/09/10 | 不变 |
| UC-09 抓取并去重 | UC-15 + UC-02/04/05/07 | 拆成"首次同步"与各源同步 |
| UC-10 自动归类 | 并入 FR-11（不再单列用例） | 归类的验收口径写进 FR-11 |
| UC-11~14 待办 | UC-16~UC-23 | 按来源拆出考试/上课/毕设/一网通办/文本草稿五类生成 |
| UC-15~17 提醒 | UC-24~UC-26 | 新增"写入学校日程" |
| UC-18 改期检测 | UC-27 | 不变 |
| UC-19~21 收藏搜索 | UC-28~UC-30 | 不变 |

| UC-24/25 源与任务 | UC-32 | 合并 |
| UC-26 用户与角色 | UC-33 | 不变 |
