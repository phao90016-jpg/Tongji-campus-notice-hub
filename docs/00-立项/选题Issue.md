## 正文

```markdown
## 一句话描述

把分散在学校官网、课程平台、GitHub 和班级群里的通知汇总到一个入口，
自动整理成可核对的待办并按时提醒——给同时跟多门课和多项校园事务的大学生用。

## 要解决的问题

群通知容易被后续消息淹没；作业或报名改期后容易沿用旧时间；
分散在各平台的收藏难以和手头的课程或项目关联。

## 目标用户

主要：需要跟进多门课程和校园事务的本科生。
次要：发布班级/组织通知的班委与学生组织干事、维护信息源的系统管理员。

## 角色（≥3）

- 学生 `student`
- 班委 / 学生组织干事 `publisher`
- 系统管理员 `admin`
- （可选）助教 / 教师

## 外部集成点（≥1）

- GitHub OAuth 2.0 第三方登录
- GitHub REST API 读取课程仓库更新
- RSS / Atom 订阅官网与竞赛栏目
- 邮件 SMTP / Webhook 提醒推送

## 三个可交付增量

- v0.1 多源接入 → 统一通知流
- v0.2 归类 → 待办 → 提醒
- v0.3 资料归档 + 管理后台

## 规模自检

| 指标 | 要求 | 本项目 |
|---|---|---|
| 可交付增量 | ≥3 | 3 |
| 用例 | ≥20（含 ≥2 非功能） | 30（含 4 非功能） |
| 分析类 | ≥15 | 20 |
| 技术风险点 | ≥1 | R1 源解析失败、R3 提醒任务丢失 |
| 用户角色 | ≥3 | 4 |
| 外部集成点 | ≥1 | 4 |

## 范围收敛说明

微信群 / QQ 群自动接收、需登录作业平台自动抓取、内容平台 OCR 导入均移出本期范围，
理由与替代方案见 `docs/00-立项/选题文稿.md` 第四节。本期采用"手动导入兜底"保证流程完整。

## 技术栈

Vue 3 + FastAPI，开发期 SQLite、部署期 PostgreSQL，GitHub Actions 做 CI。
```
