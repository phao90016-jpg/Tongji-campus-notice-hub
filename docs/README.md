## 4. 文档链可追溯要求

设计条目要能指回需求条目，测试用例要能指回需求与设计。追溯关系统一维护在
[需求追溯矩阵](02-需求规约/需求追溯矩阵.md)。

编号约定：

| 前缀 | 含义 | 示例 |
|---|---|---|
| `REQ-F-` | 功能需求 | REQ-F-012 |
| `REQ-N-` | 非功能需求 | REQ-N-002 |
| `UC-` | 用例 | UC-09 |
| `NFR-UC-` | 非功能用例 | NFR-UC-01 |
| `US-` | 用户故事 | US-003 |
| `AC-` | 分析类 | AC-11 |
| `DES-` | 设计条目 | DES-API-004 |
| `TC-` | 测试用例 | TC-UC09-01 |
| `AT-` | 验收测试用例 | AT-04 |
| `ADR-` | 架构决策记录 | ADR-0001 |

## 5. 写作约定

- 每个文档首部写清：对应检查点、负责人、状态（草稿 / 待评审 / 已评审）
- 评审必须留**缺陷清单**，不允许只写"都同意"
- 图表以 Mermaid 源文件存放在 [models/](../models/)，文档里引用，不贴截图
- 涉及 AI 参与的环节，注明工具与人的把关方式
