> 负责人：项目经理（主讲）+ 全组（分工）｜状态：草稿

## 1. 演示前检查清单

答辩前一天完成，逐项打勾：

- [ ] 系统已部署在可访问环境（非本地 localhost），或准备好稳定的本地演示机
- [ ] 演示账号已创建：学生 A、学生 B（用于越权演示）、班委、管理员
- [ ] 演示数据已造好：≥2 个订阅源、≥10 条通知、≥2 条待办
- [ ] 提醒提前量临时调整为 1 分钟（便于现场演示，答辩后改回）
- [ ] 网络确认可用（OAuth 授权、抓取源）
- [ ] 备用方案准备好：录屏 / 截图（网络故障时使用）
- [ ] 演示脚本演练 ≥2 次，控制在 12 分钟内

## 2. 演示流程（12 分钟）

| 时间 | 环节 | 演示人 | 要点 |
|---|---|---|---|
| 0:00–1:00 | 开场定位 | 项目经理 | 一句话说清"给谁用、解决什么" |
| 1:00–4:00 | **演示 1：多源聚合（功能）** | 开发 A | 登录 → 订阅 2 个源 → 抓取 → 通知流 |
| 4:00–7:00 | **演示 2：通知转待办 → 提醒（功能）** | 开发 B | 生成草稿 → 确认 → 收提醒 |

| 9:00–10:30 | **演示 4：越权拦截（非功能）** | 测试 | A 的待办被 B 请求，返回 403 |
| 10:30–12:00 | 收尾：过程留痕 | 项目经理 | 打开仓库：PR / CI / Milestone / 追溯矩阵 |

## 3. 演示 1：多源聚合（功能）

**目标**：证明"多源 → 一条流"跑通了。

1. 打开登录页，点击「使用 GitHub 登录」，完成授权
2. 进入通知流（初始为空或已有历史）
3. 添加订阅源：粘贴一个 RSS 地址 → 保存
4. 再添加一个 GitHub 课程仓库作为源
5. 点击「立即抓取」，等待 10 秒内完成
6. 通知流出现汇总结果，按时间倒序
7. 点开一条通知 → 展示原文链接跳转

**要讲的一句话**：「这两个源在真实世界里分布在两个平台，现在一个入口就能看到。」

## 4. 演示 2：通知转待办 → 提醒（功能）

**目标**：证明"通知 → 待办 → 提醒"闭环。

1. 找到一条含截止时间的通知，点「生成待办」
2. 展示草稿：系统已提取标题与截止时间，状态为「草稿」
3. 手动修改标题，确认待办
4. 设置提醒提前量为 1 分钟，把截止时间设为 2 分钟后
5. 等待，现场收到提醒（邮件 / Webhook）
6. 回到待办列表，标记为「已完成」

**要讲的一句话**：「系统只生成草稿，确认权在人——误提取不会被自动变成待办。」

## 5. 演示 3：幂等去重（非功能，对应 NFR-2）

**目标**：证明重复抓取不会重复入库。

1. 记录当前通知总数（例如 12 条）
2. 连续点击「立即抓取」3 次
3. 刷新通知流，总数仍为 12 条
4. 打开对应自动化测试，展示断言：`重复抓取 N 次，记录数不增长`

**要讲的一句话**：「真实环境里定时任务每几分钟跑一次，去重是可靠性的底线。」

## 6. 演示 4：越权拦截（非功能，对应 NFR-4）

**目标**：证明权限控制是硬的，不是只藏了按钮。

1. 用学生 A 登录，记下自己某条待办的标识（地址栏可见）
2. 退出，用学生 B 登录
3. 直接在地址栏访问 A 的待办地址（或调用接口）
4. 页面 / 响应返回 403，不显示任何内容

**要讲的一句话**：「前端藏按钮不算权限控制，后端按归属校验才算。而且不区分"不存在"和"无权限"，避免探测。」

## 7. 收尾：过程留痕（1.5 分钟）

打开仓库依次展示：

1. **Issues** —— 需求与缺陷的闭环情况
2. **Pull Requests** —— 每个都有评审记录
3. **Actions** —— CI 绿灯率
4. **Milestones** —— v0.1 / v0.2 / v0.3 的按期情况
5. **docs/02-需求规约/需求追溯矩阵.md** —— 需求 → 设计 → 测试的链路

## 8. 问答准备（8 分钟）

> 每人至少答一问。提前准备以下高频问题：

| 可能的问题 | 谁来答 | 要点 |
|---|---|---|
| 请描述你们的需求过程 | 需求分析师 | 访谈 → 问卷 → 竞品 → 规约 → 评审 → 基线 |
| 为什么选增量模型而不是敏捷？ | 项目经理 | 见[项目章程](../00-立项/项目章程.md)第 4 节 |
| 你们的架构为什么用适配器模式？ | 架构师 | 隔离 R1，新增源不改上层 |
| 提醒任务丢了怎么办？ | 开发 | 落库 + 幂等 + 启动补扫（R3） |
| 去重怎么保证不会误删？ | 开发 | 内容指纹 + 源内唯一键，只跳过不删除 |
| 哪些是 AI 写的？怎么把关的？ | AI 使用负责人 | 举证 [AI 使用台账](../08-AI使用/AI使用台账.md) |
| 微信通知为什么不做自动接入？ | 项目经理 | 无官方接口，主动收敛范围，用手动导入兜底 |

## 9. 风险与预案

| 风险 | 预案 |
|---|---|
| 现场网络不通 | 切到本地演示机；备好录屏 |
| OAuth 授权失败 | 提前登录好备用会话 |
| 抓取源临时不可用 | 切到预置的本地 RSS 文件 |
| 超时 | 砍掉演示 4，优先保功能演示 |
| 被点名讲不清自己负责的部分 | 每人提前对着自己的 PR 讲一遍 |
