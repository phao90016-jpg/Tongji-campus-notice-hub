# 验收测试用例

> ⚠️ **选题已于 2026-11-20 升级到 v3**：主源改为校内结构化接口，登录改为学校统一身份认证，用例编号由 UC-01~26 调整为 UC-01~33。本文件仍按 v2 编写，编号与范围待按 v3 重写——进度与编号映射见 [变更说明-选题v3](../00-立项/变更说明-选题v3.md)。

> 对应单元：7 测试｜检查点：期末
> 负责人：测试 / 质量工程师（**验收用例须由客户视角成员编写**）｜状态：草稿

> 与[测试用例库](测试用例库.md)的区别：用例库偏实现层（单元 / 集成），
> 本文件偏**用户视角的端到端验收**——不关心内部实现，只关心"用户能不能完成这件事"。

## 1. 编写要求

- 从用户视角描述，不出现接口路径、数据库字段
- 每条用例必须能指回需求编号
- 结果只有"通过 / 不通过"，不写"部分通过"
- 覆盖正常路径 + 关键异常路径

## 2. 验收用例

### AT-01 多源聚合（REQ-F-003 / REQ-F-006 / UC-03 / UC-06）

| 项 | 内容 |
|---|---|
| 前置条件 | 用户已登录；库中无该用户的订阅源 |
| 步骤 | 1. 添加 2 个 RSS 源<br>2. 等待或手动触发抓取<br>3. 打开通知流 |
| 预期 | 通知流按时间倒序展示两个源的通知；每条可点开查看原文；10 秒内完成展示 |
| 判定 | 通过 / 不通过 |

### AT-02 手动导入兜底（REQ-F-005 / UC-05）

| 项 | 内容 |
|---|---|
| 前置条件 | 用户已登录 |
| 步骤 | 1. 复制一段班级群通知文本<br>2. 使用「手动导入」粘贴<br>3. 查看通知流 |
| 预期 | 该通知出现在通知流中，标记来源为"手动导入"，并可生成待办 |
| 判定 | 通过 / 不通过 |
| 说明 | 这是无官方接口来源的保底路径，**必须可用** |

### AT-03 待办全流程（REQ-F-011 ~ REQ-F-014 / UC-11 ~ UC-14）

| 项 | 内容 |
|---|---|
| 前置条件 | 通知流中存在含截止时间的通知 |
| 步骤 | 1. 打开该通知<br>2. 生成待办草稿<br>3. 修改标题与时间<br>4. 确认待办<br>5. 标记为"已完成" |
| 预期 | 草稿状态为"草稿"；用户确认后变"已确认"；用户编辑结果被保留；完成后变"已完成" |
| 判定 | 通过 / 不通过 |

### AT-04 截止提醒送达（REQ-F-017 / REQ-N-003 / UC-17 / NFR-UC-03）

| 项 | 内容 |
|---|---|
| 前置条件 | 存在一条已确认待办，截止时间在未来 |
| 步骤 | 1. 把提醒提前量设为 1 分钟<br>2. 把待办截止时间设为 2 分钟后<br>3. 等待 |
| 预期 | 截止前 1 分钟（±60 秒）收到提醒 |
| 判定 | 通过 / 不通过 |

### AT-05 通知改期不覆盖用户编辑（REQ-F-018 / UC-18）

| 项 | 内容 |
|---|---|
| 前置条件 | 已有一条由通知生成的待办，且用户手动改过标题 |
| 步骤 | 1. 让来源通知的截止时间发生变化<br>2. 触发抓取<br>3. 查看该待办 |
| 预期 | 系统提示"原通知已改期，请核对"；用户手改的标题**不被覆盖** |
| 判定 | 通过 / 不通过 |

### AT-06 越权拦截（REQ-N-004 / NFR-UC-02）

| 项 | 内容 |
|---|---|
| 前置条件 | 两个学生账号 A、B，各有一条待办 |
| 步骤 | 1. A 记录自己的待办标识<br>2. 用 B 的登录态请求 A 的待办 |
| 预期 | 返回 403；响应中不含 A 的待办内容；无法区分"无权限"与"不存在" |
| 判定 | 通过 / 不通过 |

### AT-07 单源故障降级（REQ-N-005 / NFR-UC-05）

| 项 | 内容 |
|---|---|
| 前置条件 | 用户订阅了 1 个正常源和 1 个会失败的源 |
| 步骤 | 1. 让其中一个源不可用<br>2. 触发抓取<br>3. 继续使用通知流与手动导入 |
| 预期 | 失败源被标记异常/失效；正常源照常入库；手动导入仍可用；系统不崩溃 |
| 判定 | 通过 / 不通过 |

### AT-08 管理员后台（REQ-F-024 ~ REQ-F-026 / UC-24 ~ UC-26）

| 项 | 内容 |
|---|---|
| 前置条件 | 管理员账号 |
| 步骤 | 1. 查看信息源清单<br>2. 查看抓取任务与失败记录<br>3. 修改某用户角色 |
| 预期 | 三项操作均成功；操作记入审计日志；普通学生无法访问该页面 |
| 判定 | 通过 / 不通过 |
