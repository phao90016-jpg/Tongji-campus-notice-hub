# 测试计划

> 对应单元：7 测试｜检查点：第 7 次课起
> 负责人：测试 / 质量工程师｜状态：待填写

## 1. 测试目标

验证系统满足 SRS v1.0 的功能与非功能需求，重点覆盖去重幂等、提醒及时性、越权拦截。

## 2. 测试范围

| 类型 | 范围 | 负责人 | 工具 |
|---|---|---|---|
| 单元测试 | 核心模块（ingest、reminders、auth） | 开发 | pytest |
| 集成测试 | 抓取 → 去重 → 入库 → 待办生成 | 开发 + 测试 | pytest + httpx |
| 验收测试 | 按用户视角的端到端场景 | 测试（客户视角成员编写） | 手工 + Playwright（可选） |
| 非功能测试 | NFR-1 ~ NFR-5 | 测试 | 造数脚本 + 计时 |

## 3. 测试策略

- **等价类划分**：对输入字段（源地址、截止时间、导入文本）划分有效/无效等价类
- **边界值分析**：截止时间为空、提前量 0、通知正文超长、分页边界
- **异常路径优先**：源返回 304、结构损坏、重复条目、越权、服务重启

## 4. 覆盖率目标

| 模块 | 目标覆盖率 | 说明 |
|---|---|---|
| ingest | ≥80% | 去重与降级逻辑是核心 |
| reminders | ≥80% | 幂等与补扫是核心 |
| auth | ≥70% | 鉴权分支 |
| 整体 | ≥70% | 核心模块须在测试报告中声明 |

## 5. 测试环境

| 项 | 内容 |
|---|---|
| 本地 | SQLite + 本地 FastAPI |
| CI | GitHub Actions，每次 PR 自动跑单元测试 |
| 部署 | 预发布环境，用于验收测试 |

## 6. 缺陷管理

- 缺陷一律建 Issue，标签 `type:bug`，标注严重程度 S1–S4
- 缺陷闭环：新建 → 修复 → 回归 → 关闭
- 测试报告中统计：发现数、修复数、遗留数、按严重程度分布

## 7. 进度安排

| 周次 | 任务 |
|---|---|
| 第 15 周 | 测试计划定稿，用例库初版 |
| 第 16 周 | 单元测试随编码推进，CI 绿灯 |
| 课后迭代 | 集成测试、验收测试、非功能测试 |
