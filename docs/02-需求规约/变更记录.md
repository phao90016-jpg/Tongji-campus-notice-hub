# 需求变更记录

> 变更必须走「申请 → 评审 → 批准 → 关闭」流程，并在 GitHub 建 Issue 留痕。
> 不允许口头变更、不允许直接改 SRS 不留记录。

## 变更流程

1. **申请**：建 Issue，标签 `type:change`，说明变更内容、原因、影响范围
2. **评审**：需求分析师评估影响，项目经理评估排期，架构师评估设计影响
3. **批准**：项目经理签字（人守关卡），记录在本文件
4. **实施**：更新 SRS 与追溯矩阵，关闭 Issue

## 影响分析要点

变更评估时必须回答：

- 影响哪些需求条目（REQ-）
- 影响哪些用例与模型（UC-、AC-）
- 影响哪些设计条目（DES-）
- 影响哪些测试用例（TC-）
- 是否需要调整 Milestone 或增量归属
