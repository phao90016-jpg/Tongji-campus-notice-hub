# 用户故事清单

> 对应单元：2 需求调研与规约｜检查点：第 2 次课（第 10 周）
> 负责人：需求分析师｜状态：草稿，待访谈确认

> 要求：每条用户故事必须带 **Given / When / Then** 验收标准，且能指回 SRS 需求编号。
> 验收标准写成可被测试用例直接引用的形式。

## 1. 故事格式

```
作为 <角色>，
我希望 <目标>，
以便 <价值>。

验收标准：
- Given <前置条件>
  When <触发动作>
  Then <可观察的结果>
```

## 2. 已细化的故事（示例）

### US-001 登录（REQ-F-001 / UC-01）

**作为**一名学生，**我希望**用 GitHub 账号直接登录，**以便**不用再记一套账号密码。

| # | Given | When | Then |
|---|---|---|---|
| 1 | 用户拥有 GitHub 账号且本系统无该账号 | 点击「使用 GitHub 登录」并完成授权 | 系统创建本地账号并跳转到通知流 |
| 2 | 该 GitHub 账号已在本系统注册 | 完成授权 | 直接进入通知流，不重复创建账号 |
| 3 | 用户在 GitHub 授权页拒绝授权 | 授权流程结束 | 返回登录页并提示「未授权，无法登录」，不建立会话 |
| 4 | 令牌交换失败 | 回调处理中 | 记录错误日志，提示稍后重试，响应中不出现密钥或错误细节 |

### US-002 重复抓取不重复入库（REQ-F-009 / REQ-N-002 / UC-09 / NFR-UC-01）

**作为**一名学生，**我希望**同一条通知不要在列表里重复出现，**以便**不用自己分辨哪条是新的。

| # | Given | When | Then |
|---|---|---|---|
| 1 | 已订阅 1 个 RSS 源，库中已有 N 条通知 | 对同一源连续触发抓取 10 次（内容未变） | 通知总数仍为 N，无新增记录 |
| 2 | 该源新增 1 条通知 | 触发抓取 | 总数变为 N+1，且只多这一条 |
| 3 | 源返回 304 未修改 | 触发抓取 | 不产生任何新记录，不报错 |
| 4 | 源页面结构损坏导致解析失败 | 触发抓取 | 抓取失败被记录，源健康计数 +1，主流程不中断 |

### US-003 生成待办草稿（REQ-F-011 / UC-11）

**作为**一名学生，**我希望**系统从通知里自动提取截止时间并生成待办草稿，**以便**不用手动抄一遍。

| # | Given | When | Then |
|---|---|---|---|
| 1 | 通知正文含「报名截止：3 月 15 日」 | 系统处理该通知 | 生成一条待办草稿，截止时间为 3 月 15 日，状态为「草稿」 |
| 2 | 通知含两个不同截止时间（报名、材料提交） | 系统处理该通知 | 生成两条草稿，分别对应两个时间 |
| 3 | 通知未提及任何截止时间 | 系统处理该通知 | 生成草稿但截止时间为空，提示用户补充 |
| 4 | 用户未确认草稿 | 到达任何时间点 | 草稿不会自动转为「已确认」，系统不得自动确认 |
