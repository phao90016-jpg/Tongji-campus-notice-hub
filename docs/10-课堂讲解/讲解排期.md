# 课堂讲解排期

> 对应《课堂形式、内容与要求》：每次课「学生讲解 8′ × 4–5 组」，计入过程性考核
> **课堂讲解与研讨 10%**。
> 硬性要求：**每人至少主讲 1 次**，全组可见，教师现场点评。

## 1. 规则

- 每组每次课 8 分钟，超时会被打断
- 全员在场，主讲人须能回答针对本人负责部分的追问
- 讲解内容必须是**已有仓库留痕的产出**——不在仓库里的不算
- 讲完由教师点评 + 组间互评，差距直接落到下次检查点

## 2. 排期表

> 4–5 人一组，8 次课；按下表轮转即可保证每人至少 1 次，留出余量给需要的同学。

| 课次 | 周次 | 讲解主题 | 主讲人 | 讲什么（3–4 个要点） | 对应检查点 |
|---|---|---|---|---|---|
| 第 1 次 | 第 9 周 | 动员与启动 | 不讲解 | 组队选题、建仓库 | 仓库 + 选题 Issue + 调研计划表 |
| 第 2 次 | 第 10 周 | 需求调研发现 | 待填 | 干系人、业务目标、现状痛点、调研方法 | 调研报告 PR + 用户故事清单 |
| 第 3 次 | 第 11 周 | 完整需求 | 待填 | 用例图、场景、非功能需求、追溯矩阵 | SRS v1.0 + 追溯矩阵 |
| 第 4 次 | 第 12 周 | 分析建模（互查） | 不讲解 | 组间互查类图/状态图草稿 | 分析模型源文件入库 |
| 第 5 次 | 第 13 周 | 完整分析模型 | 待填 | 类与属性、协作关系、行为、可追溯性 | 分析规约定稿 + 追溯矩阵 v1 |
| 第 6 次 | 第 14 周 | 概要设计 | 待填 | 架构风格与理由、数据库、内外接口 | 概要设计 + API 契约 + ADR |
| 第 7 次 | 第 15 周 | 详细设计 | 待填 | 核心构件设计、关键技术方案、迭代计划 | 详细设计 + 部署图 + 迭代计划 |
| 第 8 次 | 第 16 周 | 迭代与 DevOps | 待填 | Issue 驱动、PR 评审、CI、里程碑、发布 | CI 通过 + 首个 Tag |

## 4. 讲稿存放

每次讲解的提纲放本目录，命名 `讲稿-第N次-主题.md`，一稿一 PR。

建议结构：

```markdown
# 第 N 次课讲解（主题）

## 1. 一句话结论
## 2. 本次交付了什么（附仓库链接 / PR 号）
## 3. 关键决策与理由
## 4. 已知问题与下一步
```

## 5. 自评清单

上台前自查：

- [ ] 能一句话说清"我们做了什么、为什么这么做"
- [ ] 展示的每份产出在仓库里能找到（PR / 文件链接）
- [ ] 8 分钟内讲完（提前掐表演练）
- [ ] 准备好回答"这块是你做的吗"
- [ ] 涉及的图能手工画出来（期末会查）
