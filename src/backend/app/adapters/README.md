# 信息源适配器

对应风险 **R1**（信息源页面结构变化导致解析失败）的应对设计。

## 契约

每个来源实现同一接口，上层只依赖统一的通知草稿：

| 成员 | 说明 |
|---|---|
| `source_type` | 该适配器负责的源类型：`rss` / `github` / `manual` |
| `fetch(source)` | 拉取原始条目；失败抛 `SourceFetchError`，不吞异常 |
| `normalize(raw)` | 转换为 `NoticeDraft`（标题、正文、链接、发布时间、附件） |

## 硬约束

1. **适配器不写库。** 只返回草稿，去重与入库由 `services/ingest` 负责——
   这样 NFR-2（幂等去重）才能被单独测试。
2. **每个适配器独立健康计数。** 连续失败 3 次 → 源状态转「失效」→ 降级为手动导入（NFR-5）。
3. **新增来源只加适配器 + 注册**，不改上层代码（可演进性）。
4. 适配器内不得出现来源特有的业务判断，归一化后一律是 `NoticeDraft`。

## 计划实现的适配器

| 适配器 | 来源 | 增量 | 备注 |
|---|---|---|---|
| `RssAdapter` | 官网 / 竞赛栏目 | v0.1 | 定时拉取 + 解析 |
| `GithubAdapter` | 课程仓库 | v0.1 | 公开 API + ETag 缓存 |
| `ManualAdapter` | 粘贴 / 分享链接 / 截图 | v0.1 | 兜底路径，永远可用 |
